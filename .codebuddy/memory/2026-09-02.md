## hover 外框反复修不掉的根因（commit 9983cd2→399a230→001a590→961b44d）

- 用户连续 3 轮反馈「hover 还有外框」，前 3 次都在 `.page-back-btn:hover` 上加覆盖（box-shadow:none / background:transparent 等）都没用。

## AI 乱码 + 追问失效 + 结构化（commit 380183e）

- 乱码 `<|object|>`：模型（DeepSeek/Qwen 系）偶发吐控制 token。新增 `stripControlTokens()` 三处调用（入库前/渲染前/存档前）；正则循环清 `<\|[^<>|]{0,64}\|>`（相邻连排要反复清），再清 `</?s|eos|endoftext|im_start|im_end>`，最后兜底剥残留 `<|` / `|>`。system prompt 末尾加硬约束禁输出控制 token。
- **追问失效根因**：`this.aiMessages` 是内存变量，popup 关闭重开后丢失 → `aiFollowUp()` 里 `if(!aiMessages.length) return` 静默失败，用户看不出原因。修复：persistAIMessages/restoreAIMessages 存 localStorage `tarot_ai_messages`；首轮/追问/成功回复都同步持久化；重开恢复结果时还原；无上下文时 toast 提示「请先生成一次 AI 解读」而非静默 return。
- 结构化详细解读：system prompt 改 5 段固定模板（整体能量 / 逐牌解读 / 对你的启示 / 今天就能做的N件事 / 一句话总结），400-600 字且要求逐张牌不漏；温度 0.7→0.65（结构化更稳），重新生成 +0.12 上限 0.95。
- 多轮渲染改「提问引文(.ai-turn-question) + 回答」成对展示，第二轮起虚线分隔。
- 教训：静默 `return` 是体验杀手——追问失败无任何提示，用户只能说"用不了"。凡是依赖前置状态的入口都要给明确 feedback。
